Lesson 04 · Phase 1

条件路由与循环控制：让工作流拥有"判断力"

⏱ 约50分钟 📝 包含2个练习

一、为什么需要条件路由？

到目前为止，我们的 Agent 工作流都是固定顺序的（Pipeline）：

START → Researcher → Writer → Reviewer → Finalize → END

但真实世界的任务往往不是线性的：

  • 如果研究结果不足，要不要重新搜索？
  • 如果文章质量合格，直接通过；不合格，打回重写？
  • 用户的问题属于哪一类，该交给哪个专家处理？

条件路由让工作流能够根据当前状态动态决定下一步走向，这是从"死板的流水线"到"智能工作流"的关键一步。

二、条件路由的核心：add_conditional_edges

LangGraph 用 add_conditional_edges() 实现条件路由：

workflow.add_conditional_edges(
    source_node,          # 从哪个节点出发
    routing_function,     # 路由函数：接收 state，返回字符串
    route_map             # 字符串 → 目标节点的映射
)

路由函数返回的字符串必须和 route_map 中的 key 完全一致，框架会据此选择下一个节点。

💡 类比理解
条件路由就像程序里的 if-elif-else，或者 switch-case。不同条件下的输出决定了流程走向。

三、完整示例：带质量审核的写作工作流

构建一个 smarter 的写作流程：

  • Researcher 搜索主题
  • Writer 写初稿
  • Reviewer 评审，给出分数和意见
  • 如果分数 < 70，打回 Writer 重写（最多2次）
  • 如果分数 ≥ 70，生成最终版本
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END
from typing import TypedDict
import operator

load_dotenv()

# ===== 状态定义 =====
class GraphState(TypedDict):
    topic: str
    research: str
    draft: str
    review: str
    score: int           # Reviewer 打的分数
    rewrite_count: int   # 已重写次数
    final_output: str

# ===== 节点 =====

def researcher_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    response = llm.invoke([
        ("system", "你是研究员。简洁有力地总结主题要点（3-5条）。"),
        ("user", f"请研究以下主题：{state['topic']}")
    ])
    return {"research": response.content.strip()}

def writer_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    context = state.get("research", "")
    if state.get("rewrite_count", 0) > 0:
        context += f"\n\n【上次审稿意见】\n{state.get('review', '')}"
    
    prompt = f"""撰写一篇关于「{state['topic']}」的技术简介（200字左右）。
要求结构清晰：概述 → 要点 → 总结。

【参考材料】
{context}"""
    response = llm.invoke(prompt)
    return {"draft": response.content.strip()}

def reviewer_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    response = llm.invoke([
        ("system", """你是技术审稿编辑。请对草稿进行评分（0-100分），并给出简短的修改意见。
严格按以下 JSON 格式输出，不要有其他内容：
{"score": 分数, "comment": "修改意见"}"""),
        ("user", f"请评审以下文章：\n\n{state['draft']}")
    ])
    
    # 解析 LLM 返回的 JSON
    import json
    try:
        result = json.loads(response.content)
        score = int(result.get("score", 50))
        comment = result.get("comment", "")
    except (json.JSONDecodeError, ValueError):
        score = 50
        comment = response.content.strip()
    
    return {"review": comment, "score": score}

def finalize_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    response = llm.invoke(f"""根据以下内容生成最终版本（直接输出文章，不要解释）：

【主题】{state['topic']}
【研究】{state['research']}
【初稿】{state['draft']}
【审稿意见】{state['review']}""")
    return {"final_output": response.content.strip()}

# ===== 路由函数 =====

def should_rewrite(state: GraphState) -> str:
    max_rewrites = 2
    if state["score"] < 70 and state["rewrite_count"] < max_rewrites:
        return "rewrite"
    return "finalize"

def should_continue(state: GraphState) -> str:
    """从 researcher 出发，总是进入 writer"""
    return "writer"

# ===== 构建图 =====
workflow = StateGraph(GraphState)
workflow.add_node("researcher", researcher_node)
workflow.add_node("writer", writer_node)
workflow.add_node("reviewer", reviewer_node)
workflow.add_node("finalize", finalize_node)

# 边
workflow.add_edge(START, "researcher")
workflow.add_edge("researcher", "writer")

# 条件路由：reviewer 之后，根据分数决定是否重写
workflow.add_conditional_edges(
    "reviewer",
    should_rewrite,
    {
        "rewrite": "writer",    # 打回重写
        "finalize": "finalize"  # 通过，生成最终版本
    }
)

workflow.add_edge("finalize", END)

app = workflow.compile()

# ===== 运行 =====
if __name__ == "__main__":
    result = app.invoke({"topic": "多Agent协同开发"})
    print("=== 最终输出 ===")
    print(result["final_output"])
    print(f"\n=== 审稿分数: {result['score']} ===")
    print(f"=== 重写次数: {result.get('rewrite_count', 0)} ===")
⚠️ 防止无限循环
条件路由容易导致死循环。务必用 rewrite_count 这样的计数器来限制最大迭代次数，否则 LLM 一直给出低分就会导致循环不止。

四、循环的两种模式

在 LangGraph 中，循环（Loop）有两种实现方式：

模式1：显式计数器（推荐）

在状态中加一个计数器字段，路由函数检查计数器来决定是否继续循环。

# 在 should_rewrite 中判断
if score < 70 and rewrite_count < MAX_ITERATIONS:
    return "rewrite"
return "finalize"

# 每次回到 writer 时递增计数器
def writer_node(state):
    new_count = state.get("rewrite_count", 0) + 1
    return {..., "rewrite_count": new_count}

模式2：interrupt（人工中断）

在循环的关键节点插入 interrupt()，让人类确认后继续执行。适合需要人工审核的场景。

from langgraph.types import interrupt

def human_review_node(state):
    result = interrupt({
        "message": "文章已完成，请确认是否通过？",
        "draft": state["draft"],
        "options": ["approve", "reject"]
    })
    # result 是人工选择的结果
    return {"human_decision": result}
💡 interrupt 是什么
interrupt() 会让工作流在这一点暂停，等待外部输入（人类决策或 API 回调），然后恢复执行。这是构建 Human-in-the-loop 的核心机制。

参考：LangGraph 条件边文档

五、三种常见路由模式

模式适用场景代码示意
二元分支 通过/不通过，是/否 return "yes" | "no"
多路路由 根据类别分发到不同专家 return "expert_a" | "expert_b" | "expert_c"
循环+退出 迭代优化直到满足条件 return "loop" | "exit"

六、条件路由新手常见错误

  1. 返回字符串和 route_map 的 key 不匹配 —— 路由函数返回了 "ok"，但 map 里只有 "pass" 和 "fail"，导致运行时错误。
  2. 忘记加终止路径 —— 条件路由必须有能到达 END 的路径，否则流程永远无法结束。
  3. 循环没有退出条件 —— 这是最常见也最危险的错误，会导致请求超时或 Token 耗尽。
  4. 在路由函数里做重型操作 —— 路由函数应该只是快速判断，不要在里面调用 LLM 或做网络请求。
