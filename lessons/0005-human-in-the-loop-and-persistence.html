Lesson 05 · Phase 1

Human-in-the-loop 与状态持久化

⏱ 约50分钟 📝 包含2个练习

一、为什么要 Human-in-the-loop？

到目前为止，我们构建的 Agent 工作流都是全自动的。但在真实场景中，很多关键决策需要人类确认：

  • 代码评审：AI 发现了安全问题，是否标记为阻塞？
  • 内容发布：文章写好了，人类编辑最后审核一次？
  • 敏感操作：要删除数据库记录，先确认一下？

Human-in-the-loop（人在回路）的核心思想是：让 Agent 处理大部分工作，但在关键时刻暂停，等待人类决策。

💡 关键认知
HITL 不是"Agent 做不了才找人"，而是主动设计的协作模式——Agent 负责高效执行，人类负责价值判断。

二、interrupt() 深入

Lesson 04 中已经初步接触了 interrupt()，现在深入理解它的工作方式。

基本用法

from langgraph.types import interrupt

def human_review_node(state: GraphState) -> dict:
    decision = interrupt({
        "type": "approval_request",
        "content": state["draft"],
        "context": {
            "score": state["score"],
            "topic": state["topic"]
        }
    })
    # decision 是人类输入的值
    return {"human_decision": decision}

执行流程

Step 1: 工作流执行到 human_review_node
    ↓
Step 2: 遇到 interrupt() → 工作流暂停，抛出 Checkpoint
    ↓
Step 3: 外部系统（或你手动）获取 Checkpoint 中的中断信息
    ↓
Step 4: 人类做出决策，通过 API 提交结果
    ↓
Step 5: 调用 graph.invoke(..., config={"configurable": {...}}) 恢复执行
    ↓
Step 6: interrupt() 返回人类输入的值，工作流继续

在 LangGraph 中恢复执行

# 运行到中断点
result = app.invoke({"topic": "LangGraph"})

# 获取最新的 checkpoint（中断信息）
checkpoint = app.get_state(config)

# 人类审核后提交结果
updated_config = app.update_state(
    config,
    {"human_decision": "approve"}  # 或 "reject"
)

# 恢复执行
final_result = app.invoke(None, config=updated_config)
⚠️ 重要概念：Config 和 Checkpoint
每次 invoke() 会返回一个 config 对象，里面包含当前执行的 thread_id 和 checkpoint。这个 config 必须保存下来，用于后续恢复执行。不要丢弃它！

三、完整示例：带人工审核的代码评审系统

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command
from typing import TypedDict
import json

load_dotenv()

# ===== 状态 =====
class ReviewState(TypedDict):
    code: str
    agent_review: str
    human_feedback: str
    final_verdict: str

# ===== 节点 =====

def code_reviewer_node(state: ReviewState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    response = llm.invoke([
        ("system", """你是资深代码评审员。请审查以下代码，重点关注：
1. 安全漏洞
2. 性能问题  
3. 代码风格
4. 潜在 bug

请输出结构化 JSON：{"issues": [...], "severity": "high|medium|low", "suggestion": "..."}"""),
        ("user", f"请审查以下代码：\n\n{state['code']}")
    ])
    
    try:
        review = json.loads(response.content)
    except:
        review = {"issues": [response.content], "severity": "medium", "suggestion": "需人工复核"}
    
    return {"agent_review": json.dumps(review, ensure_ascii=False, indent=2)}

def human_approval_node(state: ReviewState) -> dict:
    """Human-in-the-loop 节点：等待人类决策"""
    decision = interrupt({
        "message": "代码评审完成，请审核 AI 的评审结果",
        "review": state["agent_review"],
        "options": ["approve", "reject", "needs_revision"]
    })
    return {"human_feedback": decision}

def finalize_node(state: ReviewState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    
    verdict_map = {
        "approve": "✅ 通过 - 代码质量良好，可以合入主分支",
        "reject": "❌ 拒绝 - 存在严重问题，需要重新开发",
        "needs_revision": "⚠️ 需修改 - 建议按意见修改后重新提交"
    }
    
    base_verdict = verdict_map.get(state["human_feedback"], "⚠️ 未知决策")
    
    response = llm.invoke(f"""基于以下信息生成最终评审报告：

【AI评审结果】
{state["agent_review"]}

【人类决策】
{state["human_feedback"]}

请直接输出最终 verdict，格式：{base_verdict}
附加2-3条具体行动建议。""")
    
    return {"final_verdict": response.content.strip()}

# ===== 路由 =====
def route_after_approval(state: ReviewState) -> str:
    if state["human_feedback"] == "approve":
        return "finalize"
    elif state["human_feedback"] == "reject":
        return "finalize"
    else:  # needs_revision
        return "finalize"  # 也可以回到 code_reviewer 重新评审

# ===== 构建 =====
workflow = StateGraph(ReviewState)
workflow.add_node("reviewer", code_reviewer_node)
workflow.add_node("human_approval", human_approval_node)
workflow.add_node("finalize", finalize_node)

workflow.add_edge(START, "reviewer")
workflow.add_edge("reviewer", "human_approval")
workflow.add_conditional_edges(
    "human_approval",
    route_after_approval,
    {"finalize": "finalize"}
)
workflow.add_edge("finalize", END)

app = workflow.compile()

# ===== 运行（两步走：先跑 + 再恢复）=====
if __name__ == "__main__":
    # 第一步：运行到 human_approval 节点，遇到 interrupt 暂停
    config = {"configurable": {"thread_id": "review-session-001"}}
    result = app.invoke(
        {"code": "def hello(): print('world')"},
        config=config
    )
    print("=== 已暂停，等待人工决策 ===")
    print("当前状态:", result)
    
    # 第二步：人类审核后恢复
    # 实际项目中这里会有 API 接收人类输入
    # 演示中直接模拟
    updated_config = app.update_state(
        config,
        {"human_feedback": "approve"}
    )
    final = app.invoke(None, config=updated_config)
    print("\n=== 最终评审结果 ===")
    print(final["final_verdict"])
💡 实际项目中的 HITL 模式
在生产环境中，interrupt 通常配合 Webhook 或 API 使用：
  1. Agent 运行到 interrupt → 发送通知给人类（邮件/Slack/弹窗）
  2. 人类在 UI 中点击"通过"或"拒绝"
  3. 前端调用 API 提交决策 → 后端调用 update_state + invoke 恢复

四、状态持久化：Checkpoint 机制

LangGraph 内置了自动检查点（Checkpointing）机制——每次节点执行完毕后，当前的状态快照会自动保存。

为什么需要 Checkpoint？

  • 恢复执行：human-in-the-loop 中断后，可以从断点恢复，不需要从头开始
  • 时间旅行：查看历史任意时刻的状态
  • 并发安全：多线程执行时保证状态一致性

使用内存 Checkpointer（开发阶段）

from langgraph.checkpoint.memory import MemorySaver

# 创建带记忆的图
memory = MemorySaver()
app = workflow.compile(checkpointer=memory)

查看和导航 Checkpoint

# 获取当前状态
state = app.get_state(config)
print(state.values)        # 当前状态数据
print(state.next)          # 下一个要执行的节点
print(state.metadata)      # 元数据（迭代次数、耗时等）

# 获取历史所有 checkpoint
for snapshot in app.get_history(config):
    print(snapshot.values)

# 回退到上一个 checkpoint（时间旅行）
prev_config = app.get_previous_config(config)
prev_state = app.get_state(prev_config)
print(prev_state.values)
💡 生产环境推荐
开发阶段用 MemorySaver（内存），生产环境换成 SqliteSaver 或 PostgresSaver（磁盘/数据库），只需改一行代码。

参考：LangGraph Persistence 文档

五、常见错误

  1. 丢弃 config —— 每次 invoke 返回的 config 必须保存，否则无法恢复中断的工作流。
  2. 误以为 interrupt 是异常 —— interrupt 是预期行为，不是错误。不要用 try-except 包裹它。
  3. 同一线程多次 interrupt —— 一个工作流实例在同一时间只能有一个活跃的中断。恢复后再调用 update_state 才能再次中断。
  4. 状态未序列化 —— Checkpoint 需要序列化状态，避免在状态里放文件句柄、网络连接等非序列化对象。
