Lesson 01 · Phase 1

多Agent系统是什么：从直觉到概念

⏱ 约45分钟 📝 包含2个练习 ✅ 第一课

一、为什么需要多个Agent？

先从一个日常场景开始理解。想象你在写一份项目方案，需要：

  • 搜索最新的行业动态
  • 撰写技术方案正文
  • 检查语法和格式问题
  • 生成PPT摘要

一个人做，每个环节切换成本很高。更好的方式是：让每个环节由一个专门的人负责，他们之间有清晰的协作关系。

多Agent系统就是这个思路的AI版本——每个Agent是一个" specialists "，专注做一件事，协作完成复杂任务。

💡 核心直觉
一个Agent ≈ 一个专业的"虚拟同事"。多Agent = 一个虚拟团队协作。

二、Agent 是什么？

Agent不是一个魔法黑盒，它由四个基本组件构成：

组件作用类比
LLM（大语言模型） 理解和生成文本，做决策 大脑
Tool（工具） 执行具体操作：搜索、计算、写文件等 手和工具
Memory（记忆） 记住之前的对话和结果 笔记本
Prompt（提示词） 告诉Agent它是谁、该做什么 岗位说明书

来源：LangChain Agents Guide

单个Agent的能力已经很强了，但遇到复杂任务时，让一个Agent负责所有环节容易产生幻觉（hallucination）——即它可能会"自信地编造"错误信息。

多Agent系统的核心优势是：让每个Agent专注自己的领域，互相验证，从而减少错误。

三、四种核心架构模式

多Agent协作有四种基本模式，掌握它们就掌握了整个领域的基础。

模式1：Pipeline（流水线）

Agent按固定顺序依次执行，前一个的输出是后一个的输入。就像工厂装配线。

Agent A（搜索） → Agent B（分析） → Agent C（写报告）
适用场景
任务步骤固定、依赖关系明确，如：调研 → 写作 → 排版。

模式2：Orchestrator / Worker（主从）

一个中心Agent（Orchestrator）负责任务拆解和调度，多个Worker Agent各自执行子任务，最后汇总结果。


用户请求
    ↓
Orchestrator（拆解任务、分发）
    ├──→ Worker A（做数据分析）
    ├──→ Worker B（做代码审查）
    └──→ Worker C（写文档）
    ↓
Orchestrator（汇总结果）→ 最终输出
适用场景
任务可拆解、各子任务相对独立，如：代码评审团队。

模式3：Router（路由）

根据输入内容动态选择路径，决定哪个Agent来处理当前请求。

用户输入
    ↓
Router Agent（判断意图）
    ├──→ 技术问题 → Agent A（技术专家）
    ├──→ 商务问题 → Agent B（商务专员）
    └──→ 投诉问题 → Agent C（客服专员）
适用场景
输入类型多样，需要分流处理，如：智能客服系统。

模式4：Peer-to-Peer（对等协作）

Agent之间直接对话、协商，没有中心调度者。每个Agent都可以发起消息，自主决定回应什么。

Agent A ↔ Agent B ↔ Agent C
   ↑         ↑         ↑
  自由对话、协商、互相纠正
适用场景
需要高度灵活协商的场景，如：辩论式问题解决、多视角分析。

参考：LangGraph 官方文档

四、动手：第一个 Hello World

现在我们来写一个最简单的多Agent脚本。这个脚本有两个Agent：

  • Researcher：搜索并总结一个话题
  • Writer：把Researcher的结果写成一段简介

使用 LangGraph 框架（Pipeline 架构）。

步骤1：安装依赖

pip install langgraph langchain-openai python-dotenv

步骤2：创建 .env 文件

OPENAI_API_KEY=sk-your-key-here
⚠️ 安全提醒
.env 文件永远不要提交到 Git 仓库。在项目根目录添加 .env 到 .gitignore。

步骤3：编写 agent_helloworld.py

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

load_dotenv()

# --- 定义状态 ---
class GraphState(TypedDict):
    topic: str
    research: str
    final_summary: str

# --- Agent 1: Researcher ---
def researcher_node(state: GraphState) -> GraphState:
    llm = ChatOpenAI(model="gpt-4o-mini")
    prompt = f"""你是研究助理。请用2-3句话总结主题「{state['topic']}」的核心要点。
只输出总结，不要其他内容。"""
    response = llm.invoke(prompt)
    return {"research": response.content.strip()}

# --- Agent 2: Writer ---
def writer_node(state: GraphState) -> GraphState:
    llm = ChatOpenAI(model="gpt-4o-mini")
    prompt = f"""你是科技写作者。请把以下研究内容改写成一段通俗易懂的简介（100字以内）：

{state['research']}

输出格式：
【简介】
（你的改写内容）"""
    response = llm.invoke(prompt)
    return {"final_summary": response.content.strip()}

# --- 构建图 ---
workflow = StateGraph(GraphState)
workflow.add_node("researcher", researcher_node)
workflow.add_node("writer", writer_node)
workflow.add_edge(START, "researcher")
workflow.add_edge("researcher", "writer")
workflow.add_edge("writer", END)

app = workflow.compile()

# --- 运行 ---
if __name__ == "__main__":
    result = app.invoke({"topic": "多Agent协同开发"})
    print(result["final_summary"])

步骤4：运行

python agent_helloworld.py
💡 预期输出
你会看到一段关于"多Agent协同开发"的简短介绍，由第二个Agent基于第一个Agent的研究结果生成。这就是最简单的Pipeline架构多Agent系统。

教程参考：LangGraph Tutorials

五、新手最容易犯的错误

  1. 贪多嚼不烂 —— 同时学 LangGraph + CrewAI + AutoGen，结果三个都没跑通。先选一个，跑通再说。
  2. 忽视Prompt设计 —— Agent行为不稳定，80%的原因是prompt没写好，不是框架问题。
  3. 不做错误处理 —— LLM会幻觉、会超时、会失败，代码必须有 retry 和 fallback。
  4. 过早优化 —— 先跑通最简单的版本（如上面的Hello World），再考虑扩展性。
  5. 不记录学习笔记 —— 不记录就会忘记踩过的坑，下次重蹈覆辙。
