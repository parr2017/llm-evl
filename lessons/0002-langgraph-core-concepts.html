LangGraph 核心概念：节点、边与状态图

⏱ 约50分钟 📝 包含2个练习

一、为什么选 LangGraph？

LangGraph 是 LangChain 官方的多 Agent 编排框架，用有向图（Directed Graph）来描述 Agent 之间的协作关系。

你可以把一张图理解为：

  • 节点（Node） = 一个 Agent（或一个处理步骤）
  • 边（Edge） = 数据流动的方向
  • 状态（State） = 所有节点共享的"工作簿"

相比 LangChain 原有的 AgentExecutor，LangGraph 提供更细粒度的控制——你可以定义条件路由、循环、中断点，适合构建复杂的工作流。

参考：LangGraph High-Level Overview

二、图的三要素

1. State（状态）

状态是一个字典，描述当前工作流的所有信息。每个节点可以读写它。

class GraphState(TypedDict):
    topic: str         # 用户输入的主题
    research: str      # Researcher 的输出
    draft: str         # Writer 的初稿
    review: str        # Reviewer 的反馈
    final_output: str  # 最终结果
💡 设计原则
状态应该是明确的、可序列化的。避免在状态中放临时变量或复杂对象，只保留流程需要的数据。

2. Nodes（节点）

每个节点是一个纯函数，接收当前状态，返回更新后的状态（或部分更新）。

def researcher_node(state: GraphState) -> dict:
    # 读取 state["topic"]
    # 调用 LLM 做研究
    # 返回 {"research": "研究结果..."}
    pass
💡 关键规则
节点函数只返回它要更新的字段，不需要返回整个状态字典。LangGraph 会自动合并。

3. Edges（边）

边定义节点之间的连接关系。分为两种：

类型作用示例
普通边 固定流向，无条件 A → B → C
条件边 根据状态动态选择路径 B → 根据 score 决定去 C 还是 D

三、构建一个完整的 Multi-Agent 工作流

现在来构建一个三Agent协作的工作流：

  • Researcher：研究给定主题
  • Writer：根据研究结果撰写初稿
  • Reviewer：审核初稿，给出改进意见

使用 Orchestrator 风格（但实际是 Pipeline，因为顺序固定）。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
import operator

load_dotenv()

# ===== 1. 定义状态 =====
class GraphState(TypedDict):
    topic: str
    research: str
    draft: str
    review: str
    final_output: str

# ===== 2. 定义节点 =====

def researcher_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    prompt = f"""你是领域研究员。请对以下主题进行简要研究（3-5个要点）：

主题：{state['topic']}

请以要点列表形式输出，每个要点不超过50字。"""
    response = llm.invoke(prompt)
    return {"research": response.content.strip()}

def writer_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    prompt = f"""你是技术写作者。请根据以下研究内容，撰写一篇结构清晰的简介文章（200-300字）：

【研究内容】
{state['research']}

要求：
- 开头一段概述
- 中间分段阐述要点
- 结尾一段总结"""
    response = llm.invoke(prompt)
    return {"draft": response.content.strip()}

def reviewer_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    prompt = f"""你是审稿编辑。请对以下草稿进行评审，指出不足并给出修改建议：

【草稿】
{state['draft']}

请按以下格式输出：
【优点】（2-3条）
【问题】（2-3条）
【建议】（具体的修改方向）"""
    response = llm.invoke(prompt)
    return {"review": response.content.strip()}

def finalize_node(state: GraphState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini")
    prompt = f"""根据研究内容、初稿和审稿意见，生成最终版本。
直接输出最终文章，不要解释过程。

【研究内容】
{state['research']}

【初稿】
{state['draft']}

【审稿意见】
{state['review']}"""
    response = llm.invoke(prompt)
    return {"final_output": response.content.strip()}

# ===== 3. 构建图 =====
workflow = StateGraph(GraphState)

# 添加节点
workflow.add_node("researcher", researcher_node)
workflow.add_node("writer", writer_node)
workflow.add_node("reviewer", reviewer_node)
workflow.add_node("finalize", finalize_node)

# 添加边（Pipeline 顺序）
workflow.add_edge(START, "researcher")
workflow.add_edge("researcher", "writer")
workflow.add_edge("writer", "reviewer")
workflow.add_edge("reviewer", "finalize")
workflow.add_edge("finalize", END)

# 编译
app = workflow.compile()

# ===== 4. 运行 =====
if __name__ == "__main__":
    result = app.invoke({"topic": "多Agent协同开发"})
    print("=== 最终输出 ===")
    print(result["final_output"])
    print("\n=== 审稿意见 ===")
    print(result["review"])
💡 运行提示
这段代码可以直接运行。注意观察：每个节点只返回自己负责的字段，LangGraph 自动合并到全局状态中。

四、进阶：条件路由（Conditional Edge）

现实场景往往需要分支逻辑。比如：如果研究结果很短（<50字），先补充研究再写草稿；如果已经足够详细，直接写。

LangGraph 通过 add_conditional_edges 实现条件路由：

# 定义路由函数
def should_research_more(state: GraphState) -> str:
    if len(state["research"]) < 50:
        return "re_research"   # 补充研究
    return "writer"            # 直接写

# 添加条件边（从 researcher 节点出发）
workflow.add_conditional_edges(
    "researcher",
    should_research_more,
    {
        "re_research": "researcher",   # 回到自己（循环）
        "writer": "writer",            # 前进到 writer
    }
)
⚠️ 循环警告
条件路由可能导致无限循环。实际项目中应设置最大迭代次数或使用 max_iterations 参数防止死循环。

参考：LangGraph Conditional Edges 文档

五、LangGraph 新手常见错误

  1. 忘记 workflow.compile() —— 没有编译就没有可运行的 app。
  2. 节点函数签名错误 —— 必须是 (state: GraphState) -> dict，不能多参或无参。
  3. 在状态里存非序列化数据 —— LangGraph 需要 pickle/JSON 序列化状态，列表、字符串可以，但文件句柄不行。
  4. 条件边返回值拼错 —— 返回的字符串必须和 add_conditional_edges 中的 key 完全一致。
  5. 忘记添加 START 和 END —— 没有 START 入口，图无法开始执行。
